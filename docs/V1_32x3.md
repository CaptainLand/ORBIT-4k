# ORBIT-4K V1 — 32 Cell × 3 Micro Slot

## Goal

V0 represents one 4/4 measure as 96 independent Transformer timesteps. V1 keeps the exact same 1/96 chart resolution but changes the expensive temporal unit:

- 1 measure = 32 Transformer cells
- 1 cell = 3 ordered 1/96 micro slots
- 16-measure window: 1536 V0 timesteps -> 512 V1 cells
- final output is still expanded back to the original `[tick, lane]` 1/96 chart

The main purpose is to reduce Transformer sequence cost and EMPTY-dominated temporal context without throwing away 12th/24th/48th/96th timing.

## Data reuse

V1 directly reuses the existing V0 processed dataset:

```text
data/processed/v0/
  index.jsonl
  audio/*.npz
  charts/*.npz
```

No audio feature rebuild is required. `Orbit4KCellDataset` obtains the normal beat-synchronous 1/96 audio tokens and packs every three neighboring tokens into one cell on the fly.

The chart target becomes:

```text
[B, cells, 3, 4]
```

The three micro slots remain ordered. LN state exposed to the model is only the state at the beginning of each cell so the target micro slots cannot leak their answers to one another.

## Model

V1 keeps the 384-d / 6-head / 6-layer Audio Encoder / 8-layer Chart Decoder backbone.

Audio path:

```text
3 × 520-d 1/96 audio tokens
  -> shared micro projections
  -> explicit micro-position embeddings
  -> concat to 384-d cell
  -> Audio Transformer
```

Chart path:

```text
previous cell = 3 micro × 4 lanes
  -> state + lane + micro + active-LN embeddings
  -> 12 × 32-d atoms
  -> concat to 384-d cell
  -> causal Chart Transformer
```

Output:

```text
cell hidden
  -> 3-slot local micro mixer
  -> state logits [B,C,3,4,4]
  -> micro onset logits [B,C,3]
  -> cell onset logits [B,C]
```

The length-3 micro mixer is cheap compared with global attention and lets the three subslots coordinate before state prediction.

## Loss

V1 uses four terms:

```text
L = state
  + 0.35 * cell_onset
  + 0.25 * micro_onset
  + 0.10 * density
```

`cell_onset` is intentionally less sparse than the old 1/96 onset target. `micro_onset` then learns where inside an occupied 1/32 cell the event belongs.

V1 also reduces the old rare-state class boost from `[0.15, 1.0, 1.4, 1.4]` to `[0.20, 1.0, 1.2, 1.2]`, because the hierarchical onset heads already counter EMPTY dominance and the stronger V0 LN weighting contributed to inference bias.

## Warm start from V0

V1 can reuse compatible tensors from the current V0 `best.pt`:

- Audio Transformer
- Chart Transformer
- continuous BPM/SR condition network
- same-time audio gate/norm
- compatible input norm
- reduced state/lane/active-LN embeddings
- 24 -> 8 beat phase sampling
- 96 -> 32 measure phase sampling

V1-only micro input/output modules remain newly initialized.

Start from the old V0 checkpoint:

```powershell
python scripts/train_v1.py `
  --data data/processed/v0 `
  --config configs/v1.yaml `
  --run-dir runs/v1 `
  --warm-start-v0 runs/v0/best.pt
```

The Web Lab exposes the same V1 option and warm-start path.

## GPU memory and large datasets

Dataset size and per-step VRAM are different quantities.

A correct windowed DataLoader does **not** copy 1000 songs to the GPU at once. More songs normally increase:

- number of optimizer steps
- disk usage
- CPU-side cache churn
- total training time

They should not linearly increase peak GPU memory.

The dominant V0 per-sample cost is the 1536-token Transformer activation graph. V1 reduces the main global sequence to 512 cells. Attention matrices therefore have roughly:

```text
(512 / 1536)^2 = 1/9
```

of the V0 area at the same batch and window length. FFN/token-linear work is closer to 1/3. The raw three micro audio features are still retained, so total wall-clock/VRAM improvement is not exactly 9x.

`configs/v1.yaml` defaults to batch 4 / accumulation 4. For an apples-to-apples memory comparison with V0 batch 2, temporarily set V1 `batch_size: 2` and compare the recorded `peak_allocated_mb` values.

Every V1 epoch writes GPU memory diagnostics into `runs/v1/metrics.jsonl`:

```json
"gpu_memory": {
  "allocated_mb": 0,
  "reserved_mb": 0,
  "peak_allocated_mb": 0,
  "peak_reserved_mb": 0
}
```

If a 1000-song run starts normally but GPU memory climbs epoch after epoch, treat that as a leak/fragmentation issue rather than a normal consequence of dataset size.

## Preview inference

After V1 has a checkpoint:

```powershell
python scripts/generate_v1.py `
  --checkpoint runs/v1/best.pt `
  --audio "D:\Music\test.mp3" `
  --output-dir runs/v1/generated `
  --bpm 170 `
  --offset-ms 29 `
  --stars 6 `
  --measures 4
```

The V1 preview generator performs one expensive Chart Transformer step per 1/32 cell and emits all three 1/96 micro slots together. Full-song V1 stitching should be calibrated after the first V1 checkpoint is evaluated, rather than copying V0 inference thresholds blindly.
